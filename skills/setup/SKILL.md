Call the Leash check_connection tool (commonly exposed as leash_check_connection) with input {}, reason "Confirm Leash is connected", context "Leash setup". Only say connected if the result says connected true and isError false. Do not read email, files or other private accounts to test setup. If authentication is needed, let the host open Leash sign-in. Do not narrate the check or show JSON, flags, tool names, logs or credentials. After a successful check, reply with exactly: "Successfully connected to your Leash." If the check fails or needs user input, give one short next step and never claim success. This brief response format applies only to setup, not later tasks. This skill does not silently modify global instructions or claim to have saved memory. If the user separately requests a permanent preference, use the host's documented personal-instruction mechanism and preserve existing content. ChatGPT web uses Settings → Personalization → Custom instructions; Claude app uses Settings → General → Instructions for Claude; Cursor uses User Rules. Show the appropriate manual step instead of assuming chat can edit these settings. For file-capable hosts, save only the credential-free Leash rule and read it back to verify the write. Never imply a successful connection check proves that a standing rule was saved. Leash provides the setup guide at https://openleash.com/personal. Never save a token or private URL into memory or a project file.
